# A guarantee established in one unit dies silently in the unit that consumes it

## Context

The Watchtower shipped as six units, each built and reviewed on its own and each
internally correct. The whole-branch seam review then found nine real bugs, and
**five of them were the same shape**: unit A established a guarantee, unit B
consumed A's output, and B did not honour it. A's tests passed because A did its
job. B's tests passed because B was tested against fixtures B's author wrote —
fixtures that encoded B's *assumption* about A, not A's *guarantee*.

The five, concretely:

1. **A defence computed and not rendered.** The cycle-time median is defended
   structurally by collapsing each child to one per-child median first, and the
   count of rejected measurements (`droppedSamples`) is the caveat that goes with
   it. The table rendered that count only beside a "—". A row where most pairs
   were rejected but a few survived printed a real median and read *clean* — the
   rejections, which are themselves the finding, were invisible in exactly the
   branch where they matter.
2. **A field computed, projected, and read by nobody.** `FlowUnit.fromTruncatedDoc`
   was derived per unit and carried faithfully through `anonymousUnits` into the
   drill-down, where nothing consumed it. The caveat block said "abnormal docs: N"
   and the roster listed names, and staff could not join the two.
3. **"Absence is COUNTED, never FILTERED" — the branch's flagship invariant —
   broken by the consumer.** The client's `narrowProgress` claimed in its own
   docstring that a `null` return covered "children present but every one of them
   unreadable". It did not: a child whose save the server could not read narrows
   perfectly well. So the whole-cohort-unreadable state — the likeliest cause of
   which is a `DOC_VERSION` bump deployed on one side of the seam only — rendered
   as the mild "nothing here yet" line with the real cause one bullet deep in the
   caveat block. (The server side had the mirror image: three paths in the
   business walk deleted a record carrying a child's whole Phase 4-5 progress and
   flagged nothing, because a business has no `index` and so leaves no
   placeholder.)
4. **The server clamps a timestamp because it is untrustworthy; the client then
   samples that same timestamp as if it were trustworthy.** `recencyClamped` means
   "we could not trust this device's clock". It was consulted when bucketing a
   unit as active or stalled, and by nothing in the cycle-time computation — so
   one record was simultaneously "we cannot trust this child's clock" and "here is
   their cycle time". The partial case is the dangerous one: a real predecessor
   stamp beside a clamped successor yields a plausible multi-day elapsed that
   passes every other guard.
5. **A membership flag read as timing evidence.** `hasCompletionsOutsideRequest`
   is documented on the wire as a caveat count with no timing in it — true if any
   completion ever fell outside the requested window. The client used it as
   corroboration that a fresh recency was real. Because it is true forever once
   true, a child who completed one task long ago and quit corroborated every stamp
   they would ever write, for every criterion — driving the "uncorroborated
   recency" count to near-zero cohort-wide and letting a bare, completion-less
   stamp read as *actively working* on a board whose entire job is noticing who
   has stopped.

A sixth of the same family sat beside them: the WIP-concentration caveat, whose
whole job is telling staff which numbers to distrust, fired on a total that
counted business units as well as ideas — so a lawful save with the app's five
ideas plus one dangling business tripped it. A false alarm on the distrust line
is worse than no line.

## Guidance

- **Assert the invariant in the CONSUMER, phrased at the consumed surface.** A
  producer test proves the guarantee exists. Only a consumer test proves it is
  honoured. "The median excludes clamped units" is not a `flowBoard` fact — it is
  a fact about `flowBoard` reading a field the server wrote, so the test belongs
  where the reading happens and must name the field.
- **When a field's docstring states a limitation, that sentence is an assertion
  to verify against every call site, not prose.** `hasCompletionsOutsideRequest`
  said "a membership fact with NO TIMING in it" and was used as timing. Both the
  wire type's docstring and the consuming function now state the negative
  explicitly — *this is deliberately NOT one of them* — because the positive
  statement alone did not survive one unit's distance.
- **Feed the consumer the producer's REAL output, at least once.** The contract
  here is declared twice, in two repos, from one reading of one header. Nothing in
  either suite had ever seen the other's bytes. Fixed with a committed fixture
  generated by running the server's own `shapeProgress` over a representative
  store, driven through the client's real narrowing and math:

  ```ts
  // src/screens/staff/__tests__/wireFixture.test.ts
  it("narrows with ZERO rejections — every child, idea and business is readable", () => {
    const narrowed = narrowProgress(fixture);
    expect(narrowed!.rejectedChildren).toBe(0);
    expect(narrowed!.rejectedIdeas).toBe(0);
    expect(narrowed!.rejectedBusinesses).toBe(0);
  });
  ```

  Not a snapshot — a snapshot of a narrowing passes just as happily on a payload
  whose every field arrived `undefined`. Zero rejections IS the field-name check,
  and a companion test asserts every field of the contract is EXERCISED in both
  states, so a fixture of nulls cannot pin nothing while looking green.
- **Run a dead-plumbing scan on the branch, not on the unit.** Every field a unit
  adds to a shared type is a promise that a later unit will read it. Grep each new
  field for a non-test reader; a field with none is either dead or a bug wearing a
  field's costume. Instances 1, 2 and 4 above are all reachable this way in
  minutes.
- **A defence and its caveat ship together, in every render branch.** The caveat
  exists for the reader who cannot see the defence working. Rendering it only in
  the branch where the failure is already obvious is the same defect as not
  rendering it.

## Why This Matters

Per-unit review structurally cannot see this class. Each unit honestly did its
job; the invariant is a property of the JOIN, and no unit's test suite is scoped
to a join. That is not a reviewer failing — it is the ceiling of per-unit review,
and it is why a whole-branch pass is not optional bookkeeping on a multi-unit,
multi-repo feature. Five of nine seam bugs on this branch were this one shape,
which makes it the cheapest thing to look for first.

The failure is also biased in one direction: a broken composition invariant
almost always fails *silently and optimistically*. Nothing throws. Numbers still
render. A distrusted clock produces a confident median; a dead child reads as
active; an abnormal document reads as normal. On a staff tool whose only
actionable number is "who has stopped", a silent optimistic failure removes a
child from every intervention path — the exact population the board exists to
find.

## When to Apply

- Reviewing any branch whose units split producer and consumer, especially across
  a repo or a deploy boundary.
- Adding a field, flag, or defence to a shared type "for the unit that renders
  it": name that unit, and phrase its verification at the rendered surface.
- Any time a docstring on a shared type contains the words *not*, *only*, *never*,
  or *does not mean* — that clause is the invariant most likely to be lost in
  transit, and it deserves an explicit negative assertion in the consumer.
- Any pair of constants or shapes maintained in two repos with no parity gate
  (here: `DOC_VERSION` / `PROGRESS_DOC_VERSION`, and the wire contract itself).
  Either gate them or give the skew state its own loud surface.

## Examples

Fixed on `feat/watchtower` (uncommitted at the time of writing). `droppedSamples`
renders in all three median branches; `DrillDownEntry.fromTruncatedDoc` carries
the abnormal-save marker onto the roster name so the caveat count can be joined
to a person; `allUnreadable` gets its own `role="alert"` state naming the
deploy-skew cause; `computeFlowRows` drops and counts pairs from any clamped
unit; and `isRecencyCorroborated` now reads a real timing number
(`lastCorroboratedCompletionAt`, added to the wire — the newest stamp that
actually has a completion behind it) instead of the timing-free membership flag,
with the flag demoted in both docstrings to caveat-count duty and the old
in-window test kept as the fallback for a server that predates the field, so a
deploy skew costs credit rather than granting it. The concentration caveat fires
on `maxIdeaUnitsPerChild` while still displaying `maxUnitsPerChild` — the test
for a concentration and the size of one are different numbers.
